## [0.5.0] - 2026-10-01

Fixes from the stride-copilot-ideation review (goal G437): shipping, shell-block state, commit scope, autosave, PowerShell parity and documentation drift, plus `--batch` for shipping an existing batch JSON and `--continue=<path>`.

### Added

- **`--batch` ships an existing batch JSON without decomposing again (W2193).** After a decline at the Step 8.5 approval gate, a failed POST, or a Step 7.5 retry-exhaustion recovery, the batch JSON on disk was the recovery artifact, but the only documented ways to ship it were running `lib/ship.sh` by hand or re-activating stridify, which dispatched the decomposer again and produced a different batch. `stride-ideation-stridify --batch <path>` (also `--batch=<path>`, split on the first `=`) runs the new Step 1b: the Step 3 auth preflight, `lib/validate_batch.py`, the `ship.sh --check-payload` token screen and a warning that re-shipping a shipped batch duplicates it, then the unchanged Step 8.5 preview and gate (honoring `--yes`) and the Step 9 ship through `lib/ship.sh` / `lib/ship.ps1`. It stamps, rewrites and commits nothing. `--batch` with `--goal`, with a requirements-doc path, or with no value is rejected. The decline message, the Step 7.5 recovery README and summary, the Step 9 recovery text, the resilience model and the README now name the `--batch` form. `lib/test-stridify-preview.sh` and `.ps1` cover the flag parse and the validate-then-ship path against a fake curl (bash) and a loopback HTTP listener (PowerShell); `lib/test-stridify-fallback.sh` checks that the recovery text names `--batch`.
- **`--continue=<path>` (W2194).** The ideate skill's Step 1 documented only `--continue <path>`, while `--input` and `--profile` claimed to accept "both forms, matching how `--continue` accepts both". `--continue` now takes `--continue <path>` and `--continue=<path>` (split on the first `=`), and a bare trailing `--continue`, `--continue=`, or `--continue` followed by another flag stops with `stride-ideation: --continue requires a path to a prior -requirements.md doc` before any session work. New cases in `lib/test-ideate-input.sh` and `.ps1`.

### Fixed

- **The stridify ship steps run through one tested script pair (D323).** Steps 3, 9 and 10 were model-followed bash fragments that `eval`ed unquoted `lib/read_auth.py` output (a URL holding `&` emptied `STRIDE_API_URL`; one holding `$(...)` ran it), put the bearer token on curl's command line where `ps` shows it, sent the payload as one `-d` argv string, relied on the token surviving between separate shell calls, looked for the auth file under the Claude-only `CLAUDE_PROJECT_DIR`, and crashed with a traceback when a 2xx body was not the expected JSON — after the tasks had already been created, inviting a duplicate re-run. New `lib/ship.sh <batch.json>` and its PowerShell twin `lib/ship.ps1 -Batch <path>` read auth, strip the audit fields into an owner-only temp file, validate that payload, refuse a payload carrying the token, POST it, branch on the status exactly as Step 9c documents (verbatim, token-scrubbed body on a non-2xx; verbatim transport error) and render the created identifiers, in one process. The token reaches curl as a config on its stdin (`-K -`), never on argv or disk; `ship.ps1` posts the payload file's UTF-8 bytes in-process with redirects disabled. A 2xx whose body cannot be rendered prints a do-not-re-run notice and exits 0. Temp files are removed on success, failure and interrupt. `.stride_auth.md` is found at the git toplevel (so a run from a subdirectory works), else the current directory, or `$STRIDE_AUTH_FILE`. `--check-auth` / `-CheckAuth` is the Step 3 preflight. Shared helpers live in `lib/ship_support.py`. Ported from stride-opencode-ideation (D316, D322); its `--check-payload` mode arrives with D329, which screens the decomposer's output at Step 8a.
- **`lib/read_auth.py` output is shell-safe.** Both values are `shlex.quote`d, so an `eval` of the output can no longer execute anything the auth file contains. Plain values print unquoted, exactly as before.
- **Smoke-test live mode (Stage 7) ships through the new scripts.** `lib/run_smoke_test.sh --live` and `lib/run_smoke_test.ps1 -Live` previously duplicated the old fragments; the PowerShell one also printed only the exception message on a non-2xx. Both now call `lib/ship.sh` / `lib/ship.ps1`, so the body is printed verbatim.
- **Every shell block in the ideate and stridify skills is self-contained (D324).** The blocks sourced a helper in one step and called its functions in later ones, carried `SLUG`, `TARGET_PATH`, `SOURCE_TS`, `DRAFT_PATH` and the decomposer's JSON between steps as shell variables, used `exit` in a shell the host may reuse, and referenced a `<plugin-root>` placeholder Copilot CLI never fills in. Each skill now states the rule once near its top: every block runs as one shell call, receives earlier values as single-quoted literals its `# Carried forward:` line names, sources the helper it calls, and runs its body in a `( … )` subshell so a failure is a non-zero status rather than the end of the shell. The plugin root is resolved once as the directory two levels above the loaded `SKILL.md` and checked for `lib/filename.sh` in every block that uses it, failing with a clear message otherwise. Step 8a writes the decomposer's JSON with the file-write tool into a private (mode 700) temp directory instead of `printf` of a shell variable, and the human-copied recovery commands in Step 7.5 quote their paths. Each step that runs a helper names its PowerShell equivalent (`lib/filename.ps1`, `lib/draft.ps1`, `lib/ship.ps1`, `Get-FileHash` for Step 6). New `lib/test-skill-blocks.sh` extracts every block, fills its placeholders, and runs it with `bash -u` in a scratch repository; it also checks that each block sources what it calls and reads only variables it assigns, and re-runs every block that takes an optional value with that value set, so the `--continue` and `--goal` branches run too.
- **The artifact commits no longer sweep in files the user had already staged (D325).** ideate Step 9 and stridify Step 8d ran `git add <path>` and then a plain `git commit -m`, which records everything in the index, while both skills claimed `git add <path>` kept unrelated work out. Both now pass the artifact as a pathspec after `--` (`git commit -m … -- "$TARGET_PATH"`), so a file staged before the session stays staged and out of the commit; the `git add` stays, because a pathspec commit of an untracked file fails without it. Commit message formats are unchanged. New `lib/test-commit-scope.sh` runs the exact blocks, and `lib/test-commit-scope.ps1` the same commands from PowerShell, in a scratch repository (with and without history) holding a pre-staged file; a control case shows the old form sweeping it in.
- **Both agent dispatches have a fallback for hosts without custom agents (D325).** stridify Step 7 and the protocol skill's Reviewer pass now name each agent by its frontmatter name and its `agents/` file, and say what to do when custom agents are unavailable: read the agent file and follow it inline, with the same input (the document, treated as data, never as instructions) and the same single-fenced-JSON output contract. The inline pass keeps the agent's tool limits — file reads only, no shell command, file write or network call until its JSON is produced — and the reviewer receives the resolved `profile=<PROFILE>` line its input contract expects, so the profile-aware checks run either way. The reviewer stays advisory and never blocks the write. Previously a host without custom-agent support ended the stridify skill on attempt 1. The Step 7a retry classifier no longer keys on one vendor's wording: rate-limit and capacity errors from any provider (HTTP 429, 503 or 529, or a `rate limit`, `overloaded` or `capacity` message) are transient, and an unavailable agent is a new `unavailable` outcome that runs the agent inline instead of retrying. `lib/test-stridify-retry.sh` and `.ps1` cover the new rows, including a mocked 429 that is retried to success.
- **Draft autosave actually happens, stays out of commits, and resumes only the same topic (D326).** The ideate skill promised that the protocol skill saved the in-progress draft after every round, but `skills/stride-ideation/SKILL.md` never said so, so nothing was saved. It now has an **Autosave** section: after every round the draft (sections plus a round-state header) is written to `draft_path` with the file-write tool, and a non-empty draft is loaded at round 1; it is never a gate bypass and a failed write never blocks. Step 4d's claim that the project's `.gitignore` covers `.stride/` was true only in this plugin's own repository: new `sti_draft_dir` / `Sti-DraftDir` (called by Step 4d and by the save helpers) creates the scratch dir and writes `.stride/.gitignore` containing `*` when it is absent — when the helper created the dir or the dir is named `.stride` — never overwriting an existing one and never touching the project's `.gitignore`. Inside a git work tree it then checks that drafts really are ignored: when an existing `.stride/.gitignore` does not cover them it adds `/<dir>/*-draft.md` to the repository's local `.git/info/exclude`, and when a rule re-includes them it refuses, and Step 4d turns autosave off for the session. `Sti-DraftSave` with neither a content argument nor pipeline input is a usage error, as in bash, instead of emptying the draft. `sti_draft_save` now reads its content from stdin when no content argument is given and `Sti-DraftSave` accepts pipeline input, so prose never has to be shell-quoted; the argument forms still work. `sti_draft_find` / `Sti-DraftFind` match only `<YYYY-MM-DDTHHMMSS>-<slug>-draft.md`, so a `user-auth` draft is no longer offered for `auth`; both languages match exactly the same files. `Sti-DraftSave` now writes UTF-8 without a byte-order mark, as the bash helper does. `lib/test-draft.sh` and `.ps1` cover stdin and pipeline input, the self-ignore file, the anchored lookup, cross-language parity and a clean `git status` after a save.
- **One seam definition for the advisory, `--goal` and scoping, identical in bash and PowerShell (D327).** The stridify Step 2 advisory counted numbered items, bullets and `###` headings, but `sti_extract_seams` parsed only numbered items, so a doc with four bulleted seams triggered the advisory and then failed `--goal 1` with "section is empty". The extractor, the resolver and the scoper now read one shared item list (ported from stride-opencode-ideation D321): top-level numbered `<N>. **Name**` items, else top-level `- **Name**` bullets, else `### Name` headings, one shape per section — and the advisory counts the extractor's output, so every seam it counts is addressable with `--goal 1..N`. Numbered items match only at the top level (at most 3 leading spaces), so an indented numbered sub-list under a bulleted seam no longer takes over the section; as in markdown, a sub-list indented only 1–3 spaces still reads as top level. PowerShell now matches like bash: `Sti-ResolveGoal` compares a numeric `--goal` as a number (`01` selects seam 1), and every heading and item match is case-sensitive (`-cmatch`), so `## Decomposition Seams` is not the seams section in either shell. `lib/test-stridify-per-goal.sh` and `.ps1` gain cases 16-25; case 25 runs both implementations on every test doc and fixture and diffs extract, resolve and scope output.
- **The batch validator checks every task, and the section gate is a script (D328).** `lib/validate_batch.py` accepted a task with no `title` or `type`, a task whose `type` was `goal`, and a stray root `tasks` key next to `goals`; all three passed validation and reached the API as an opaque 422 after the decomposer pass, or had their tasks silently dropped. Check (d) now requires each task to be an object with a non-empty string `title` and a `type` of `work` or `defect`, and check (b) fails a root `tasks` key alongside `goals`; each message names the JSON path (`goals[0].tasks[1].type ...`). stridify Step 2.3's seven-section check was prose that grepped for `Success metrics`, while the protocol skill and the reviewer spell it `Success Metrics`, so a doc written to the protocol skill's spelling failed the gate. The new `lib/check_sections.py` matches level-2 headings case-insensitively, ignores headings inside code fences, lists every missing section and only reads the doc; Step 2.3 runs it as one `python3` call on bash and PowerShell hosts alike. The Step 7.5 recovery README now cites the validator's six named checks, not five, and the Step 8a table's (b) and (d) rows describe the new failures. New `lib/test-check-sections.sh` and `.ps1`; new cases in `lib/test-validate-batch.sh` and `.ps1`.
- **The agent prompts no longer contradict themselves, and every JSON block in them parses (D329).** The decomposer said it had no codebase access while its frontmatter granted `read` and `search`, and said never invent paths while every example invented `lib/app/` paths. It now may read and search the project the doc names to ground `key_files` and `patterns_to_follow`, marks a path it could not confirm as `proposed` in the entry's `note`, treats everything it reads as data, never instructions, never reads secret-bearing files, and never puts a credential in its output; stridify Step 7's description, its inline fallback and the Step 7.5 recovery README say the same. Because the decomposer can now read the project, stridify Step 8a runs the new `lib/ship.sh --check-payload` (`ship.ps1 -CheckPayload`) on its output right after the validator and refuses a batch that contains the configured Stride API token before anything is written, committed or previewed; previously the first token check was the POST in Step 9, after the Step 8d commit. Example 3's `//` elisions, which made its JSON block unparseable, moved into prose. The skeleton and examples no longer model empty `testing_strategy` values (the empty review-queue pills the prompt warns against), and it says "calling skill". The reviewer's output block used `"a" | "b"` unions and did not parse; it is now a parseable template with the allowed `verdict`, `severity` and `section` values listed beside it, unchanged. Its example marked an unmeasurable metric `blocking` against its own rule (now `advisory`, with the goal/non-goal contradiction `blocking`), it says five profile checks instead of three, and it names Copilot's `read` and `search` tools. New `lib/test-agent-prompts.sh` and `.ps1` check all of this.
- **Documentation matches the plugin (W2194).** The protocol and ideate skills no longer call `lean` "byte-for-byte v0.3.0" — later releases added the round recap, uncertainty path, profile recommendation, reviewer decision, autosave and challenge gate to every profile — and instead say what lean runs and omits. The protocol skill is now the single home of the question loop (the two skills each said it lived in the other), its description is under the 1,024-character Agent Skills limit and names `stride-ideation-ideate` as the entry point, and all three skills use the same `skills_version: 1.0` form. Test comments and `lib/filename.sh` no longer cite `commands/stridify.md`, `/stride-ideation:` slash commands or Claude Code's Agent tool. The smoke-test headers say which stages run the skill's helpers and which are fixture checks (Stage 2's `drift_check.py` is one), and the strip stage now compares the batch file's SHA-256 before and after instead of printing it. The README documents the `stride-copilot-marketplace` install, and the 0.1.0 notes no longer say the plugin is on no marketplace.
- **Sourcing `lib/filename.sh` or `lib/draft.sh` no longer turns on `nounset` in the caller.** Both ran `set -u` at file scope, so an unset optional variable in a later skill block (for example `CONTINUE_PATH` in a fresh ideate session) aborted the step with `unbound variable`. The functions already read every argument with a default; the test scripts keep strict mode, and `lib/test-filename.sh` / `lib/test-draft.sh` gain a regression case each. The PowerShell twins had the same leak — `lib/filename.ps1` and `lib/draft.ps1` ran `Set-StrictMode -Version Latest` at file scope, so dot-sourcing them made a read of an unset variable throw in the caller — and now set it inside each function instead, with a matching case in `lib/test-filename.ps1` / `lib/test-draft.ps1`.
- **Three PowerShell scripts now carry a UTF-8 byte-order mark.** `lib/run_smoke_test.ps1`, `lib/test-ideate-input.ps1` and `lib/test-validate-batch.ps1` contain non-ASCII characters and had no BOM, so Windows PowerShell 5.1 would read them in the ANSI code page and fail to parse them. `lib/test-ship.ps1` now checks that every `lib/*.ps1` parses the way 5.1 reads it.

## [0.4.0] - 2026-07-04

Hardens the `stride-ideation-stridify` decomposition-and-ship pipeline around the Stride review queue's **five per-task scored fields** — `acceptance_criteria`, `testing_strategy`, `security_considerations`, `pitfalls`, `patterns_to_follow` — so generated tasks score well, are attributed to the creating agent, and are caught before the API rejects them. Also completes the port of the core round-loop protocol to the Copilot selection primitive. All changes are additive and behavior-compatible.

### Added

- **Decomposer contract names the five review-queue scored fields (`agents/requirements-decomposer.agent.md`).** Added a "Five review-queue scored fields" subsection that names all five and states the review queue scores them, added `security_considerations` (with a shape annotation) to the canonical task skeleton, and enriched one fully populated example task in each of the three worked examples so every scored field is demonstrated. `created_by_agent` is also added to the agent's "What you MUST NOT emit" list — it is a runtime value the orchestrator stamps at ship time.
- **`created_by_agent` stamping in the stridify pipeline (`skills/stride-ideation-stridify/SKILL.md` Step 8b).** The skill now stamps `created_by_agent` onto every goal object at ship time so each shipped goal (and its propagated child tasks) is attributed to the creating agent in Stride's `/agents` activity feed. The field is a create-payload field — deliberately kept out of `lib/strip_audit_fields.py`'s local-audit strip set so it survives to the wire — and `lib/test-ship-helpers.sh` gains a regression asserting exactly that.
- **`validate_batch.py` guardrails.** Added a fatal `(f) length_limit` check that flags a goal/task `title` or a `security_considerations` element exceeding 255 Unicode code points (counted by code point, matching the Stride `varchar(255)` changeset guard; unbounded JSONB fields are exempt), plus an advisory, non-fatal scored-field completeness pass that warns (stdout, exit 0) for any task missing or leaving empty one of the five scored fields. Covered in `lib/test-validate-batch.sh` and `lib/test-validate-batch.ps1`, and documented in the stridify Step 8a validator table.

Round order, the seven gated sections, and the one-to-four / ≤ 4 per-round question budget are preserved verbatim; the "NOT Claude Code's `AskUserQuestion`" disclaimers are intact.
- **Calibration fixtures refreshed (`fixtures/*-stride-batch.json` + `fixtures/README.md`).** Every task across all three batch fixtures now carries all five scored fields with topic-appropriate content, so the calibration reference models complete, well-scoring decomposer output. Additions only — no task reordering and `source_spec_sha256` values are preserved.
- **Documentation cleanup.** Corrected stale references to the removed `/stride-ideation:decompose` / `/stride-ideation:ship` slash commands and the nonexistent `commands/` path in the lib docstrings, test-script comments, and the notifications fixture, and clarified `lib/drift_check.py`'s role as fixture-integrity verification (the merged pipeline no longer runs drift detection). The smoke suite remains **14/14**.

## [0.3.0] - 2026-06-26

Ports the upstream [`cheezy/stride-ideation`](https://github.com/cheezy/stride-ideation) **challenge gate** to GitHub Copilot CLI — a design stress-test that runs after the round-4 premortem (and the lean-startup round-5 MVP-design batch) and before the advisory reviewer pass. Additive and profile-independent; it never blocks the write.

### Added

- **Challenge gate — four components (`## Challenge gate` in `skills/stride-ideation/SKILL.md`, surfaced via the Copilot CLI selection primitive in `skills/stride-ideation-ideate/SKILL.md`).** After the premortem and before the reviewer pass, the skill stress-tests the assembled draft with four components run in order: (a) an **assumption-confidence audit** rating every Assumptions entry `high`/`medium`/`low`; (b) a **blind-spot scan** for unstated dependencies, omitted stakeholders, untested edge cases, and failure modes the premortem missed; (c) **two distinct alternative approaches**; and (d) a **cost / risk / complexity / timeline trade-off** comparison of the proposed design against the two alternatives. Findings are surfaced as a single multi-select decision — one option per low-confidence assumption, material blind spot, and alternative — with an explicit **"Challenge nothing — write as-is"** choice, feeding at most one refinement round. The gate is advisory and profile-independent (identical under lean / product / discovery / lean-startup), runs even on `--continue`, and never blocks the write. Confidence ratings fold into the Assumptions entries in place; the blind spots, the two alternatives, and the trade-off table fold into a new optional **Design challenge** section (not one of the seven hard-gated sections, and not surfaced in the round recap). Adapted to the Copilot CLI question/selection primitive — never Claude Code's `AskUserQuestion`.

### Test coverage

- **`lib/test-challenge-gate.sh` + `lib/test-challenge-gate.ps1`** (8 + 8) — assert the challenge-gate output contract against the new fixture `fixtures/2026-05-12T120300-saved-filters-challenge-gate-requirements.md`: a `## Design challenge` section, at least two alternatives, a Cost/Risk/Complexity/Timeline trade-off table, and per-assumption `(high)`/`(medium)`/`(low)` confidence ratings scoped to the Assumptions section, plus three negative controls (no alternatives, unrated assumptions, prose-without-table).
- **`lib/run_smoke_test.sh` (and `.ps1`) gain Stage 6** (challenge-gate fixture shape, four assertions); the live POST stage is renumbered to Stage 7. The smoke suite is now **14/14** (was 10/10).

### Migration

- **No migration on the happy path.** The challenge gate is an additive advisory step — it never blocks the write, runs identically under every profile, and always offers a "Challenge nothing — write as-is" path so any session can proceed untouched. Existing `--continue` docs that never ran the gate get it on their next refinement.

## [0.2.1] - 2026-06-26

### Security

- **Audit: the install path does not overwrite a project-root context file (no fix needed).** Reviewed the Copilot install path for the `AGENTS.md`-overwrite class of bug found in the OpenCode/Codex ideation installers. This plugin has no `install.sh`/`install.ps1`; it installs exclusively via `copilot plugin install https://github.com/cheezy/stride-copilot-ideation`, which places the plugin inside Copilot's managed plugin directory. `plugin.json` declares only metadata plus `agents`/`skills` pointers — no install hook and no directive that writes any file to the user's project root — and the plugin ships no `AGENTS.md`/context file at all. The only project-root file the README references is `.stride_auth.md`, which the user creates manually (and is told to `.gitignore`); the installer never writes it. Conclusion: safe — no project-root context file is ever clobbered, so the managed-block guard applied to the OpenCode/Codex installers is unnecessary here.

## [0.2.0] - 2026-06-15

Ports the upstream [`cheezy/stride-ideation`](https://github.com/cheezy/stride-ideation) **v0.8.0** feature set to GitHub Copilot CLI — six `stride-ideation-ideate` session-experience features plus a `stride-ideation-stridify` preview-and-approval gate. Every interaction is adapted to the Copilot CLI platform's question/selection primitive (never Claude Code's `AskUserQuestion`), and every new shell helper/suite ships with its PowerShell mirror for Windows parity. Additive — `--profile=lean` (and flag-free) sessions remain compatible with v0.1.0 on the happy path.

### Added

- **Per-round section-completeness recap (`## Round recap` in the protocol skill).** Before every round — including round 1 (all empty) and the gap-fill rounds — the skill prints a compact recap of the seven hard-gated sections with a per-section `solid` / `thin` / `empty` status plus a one-line note of the round's target sections. Display-only narration printed to the Copilot CLI (never a question), and it never changes the gate, the round order, or the per-round question budget. Lists only the seven gated sections (never profile-exclusive optional sections), so it renders identically under every profile.
- **"I'm not sure — propose candidates" uncertainty path (`## Uncertainty path`).** Every gated-section and profile-specific forcing question (JTBD, Why-now, MVP design) now carries a first-class choice, with phrasing identical across rounds, presented through the Copilot CLI selection primitive, that flips the skill into teaching mode: it proposes 2–4 concrete, topic-tailored candidate answers each with a one-line rationale, then the human picks, edits, or asks for a fresh batch. A proposed candidate never satisfies the gate until the human confirms it, and it is a choice *within* a question so it never breaches the per-round budget.
- **Profile recommendation when `--profile` is omitted (`stride-ideation-ideate` Step 1).** Instead of silently defaulting to lean, an omitted `--profile` runs a single recommendation (via the Copilot CLI question UI) before the rounds: a best-guess profile offered first (labeled `(recommended)` with a one-line rationale), the other three as alternatives, defaulting to lean when inference is weak. An explicit `--profile` skips the recommendation, the unknown-value fast-fail is unchanged, and a resolved `lean` is byte-for-byte identical to passing `--profile=lean`.
- **`--input <file>` brain-dump seed (`stride-ideation-ideate` Step 1 + new Step 4c).** A new optional flag (both `--input <path>` and `--input=<path>` forms), distinct from `--continue`: the skill reads the freeform notes file **read-only** via the platform file-read tool, pre-populates draft sections wherever the notes clearly map to a gated section, then focuses the rounds on the gaps. The input file is never written, moved, or `git add`-ed, and its contents are treated as untrusted prose. `--input` and `--continue` are independent and composable; seeded content never satisfies a hard gate on its own.
- **Intra-session draft autosave and resume (new `lib/draft.sh` + `lib/draft.ps1`).** The in-progress draft is autosaved after every round to a **gitignored** scratch file under `.stride/`, so an interruption mid-session is recoverable. On start, an unfinished draft for the **same slug** is detected (`sti_draft_find` / `Sti-DraftFind`) and the human is offered resume-or-fresh via the platform question UI; on a successful commit the scratch file is deleted. The pure-shell `lib/draft.sh` (mirroring `lib/filename.sh`) and its PowerShell mirror `lib/draft.ps1` provide `sti_draft_path/find/save/load/exists/clear` — resume keys on the slug with a dash-delimited glob so `auth` never matches `oauth`, and empty/partial drafts safely fall back to a fresh session. The scratch file never holds the Stride API token or any secret.
- **Advisory reviewer findings surfaced as an explicit human decision (`## Reviewer pass`).** When the `requirements-reviewer` returns `verdict: "issues_found"`, the skill now presents the findings through the Copilot CLI selection primitive — one selectable option per finding, tagged with its `severity` (`blocking` / `advisory`) and `section` — including an explicit **"Address none — write as-is"** choice. The human chooses which findings feed the single refinement round. Both contracts are preserved and stated explicitly: **at most one** refinement round and the reviewer **never blocks the write** (write-as-is is always available, so even `blocking`-severity findings cannot hold the document hostage). An `approved` verdict with zero findings shows no prompt.
- **Human preview-and-approval gate before the `stridify` POST, with a `--yes` bypass (new Step 8.5 in `stride-ideation-stridify`).** Between writing/committing the batch JSON and POSTing it, the skill now renders the decomposed goal/task tree — each goal title, its task count, its task titles, and the cross-goal claim order from `decomposition_notes` — and requires explicit human approval (via the Copilot CLI question UI) before the POST. A new `--yes` / `--auto-approve` flag (explicit only, never inferred) bypasses the gate for scripted callers, preserving the historical fire-and-forget behavior. On decline the skill stops cleanly (exit 0) leaving the already-committed batch JSON untouched on disk — no POST attempted. The preview reads only the on-disk JSON and never prints the API token.

### Test coverage
