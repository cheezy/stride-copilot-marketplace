## [0.5.1] - 2026-11-08

This entry ports upstream `cheezy/stride-security-review`'s probe hardening, which upstream records under its 2.7.3 entry: W2670 (`275e87a`) and the two W2671 fixes after it (`dc648f3`, `97a3e32`). **None of it has run in a live Copilot CLI session.**

### Security

- **The probe command ends the snippet it starts, keeps it off your terminal, and on Linux hides all of `/var` and refuses when a host socket is reachable (W2672: upstream W2670, `275e87a`).** The block in `skills/security-review-essentials/modes/reproduction.md` is now upstream's 21 lines at `97a3e32`, byte for byte, behind this file's two-space bullet indent:
  - **The EXIT trap kills what the command started, then unlocks and removes the copy.** It keeps the snippet's process group and process ID in `g` and `p`, kills each only while it is set, then unlocks the copy's directories with `(box env -i PATH="$PATH" find "$r" -type d -exec chmod u+rwx {} \;)` before `rm -rf "$d"`. The unlock runs inside the box, so a link a surviving process swaps in cannot turn it on a file outside the copy; if the box cannot start again at exit, nothing is unlocked.
  - **macOS: the snippet leads its own process group, whatever shell runs the command.** `box` runs `exec sandbox-exec` and starts the snippet through `/usr/bin/env -i /usr/bin/perl -e 'setpgrp(0, 0); ...'`, a new line refuses to probe without `/usr/bin/perl`, and the profile adds `(deny file-read* (regex #"^/dev/tty"))`.
  - **Linux: all of `/var` is empty, and a bounded search refuses on a reachable socket.** `box` runs `exec bwrap` with `--tmpfs /var` in place of `--tmpfs /var/tmp`. Before it, `timeout -k 2 10 find /` searches outside the hidden trees, and the command refuses to probe when it finds a socket, a named pipe or a second path to your home directory, when it fails or times out, or when the home path holds a `*`, `?` or `[`.
  - **The snippet runs in the background with no input, and its output comes back through `| /bin/cat`.** The command waits for it and prints `snippet exit: <n>`.
  - **The residuals are named** in the mode file, the README and the essentials skill: on macOS a process that leaves the snippet's process group (`setsid()`, `setpgid()`) can outlive the command, still inside the box; on either system a command killed with `SIGKILL` cleans nothing up; on Linux the search cannot see a bind mount, outside your home directory, of a directory inside it, and looks only once. The left-behind paragraph adds that a surviving process can create the copy's directory again.
- **No tool the probe command runs outside the box is found through an empty or relative `PATH` entry (W2672: upstream W2671, `dc648f3`).** A new second line drops every empty or relative entry from `PATH` and refuses to probe when none is left, the trap runs `cd /` before its first lookup, and the pipe at the end names `/bin/cat`, since it starts from the project root before that line runs.
- **The exit trap looks its tools up only in the system directories, and a relative `TMPDIR` is refused (W2672: upstream W2671, `97a3e32`).** The trap sets `PATH=/usr/bin:/bin:/usr/sbin:/sbin` straight after `cd /`; where `sandbox-exec` or `bwrap` is installed outside those four directories, it cannot start the box again to unlock the copy. A check before `mktemp` refuses a relative `TMPDIR`, which the trap, from `/`, would miss. An absolute `PATH` entry inside the repository, such as a project `bin` directory that direnv adds, is still searched until the trap runs: the mode file, the README and the skill say to grade by reading when `PATH` holds one, rather than that no file in the repository can run in a tool's place.
- **Adapted for Copilot CLI (W2672).** The mode file keeps this plugin's intro line, its bullet layout and indent, and `execute` as the tool name in the reproduction rule; upstream's new text names no tool, and no Copilot-only line is added, so the pin's label "the probe block is upstream's, line for line" stays true. `README.md` takes upstream's new *That copy is* paragraph whole. The essentials skill takes upstream's new read-only paragraph and keeps its sentence on the frontmatter limit of `execute`. The guard and copy-step lines are unchanged, so `scripts/check_git_hardening.sh` needs no edit and still passes.
- **`scripts/check_agent_contract.sh` (W2672).** The whole-block pin `PROBE_BLOCK_WANT` is upstream's 21 lines, indented for this file. Two rows the old text satisfied are gone ("the copy is gone before return" and "the prose names the Linux socket limit"), and five follow their changed lines: "the Linux sandbox isolates everything" now needs `--tmpfs /var`, "the probe removes its copy on exit" the new trap's ending, "the macOS box denies every write outside the copy" the profile now ending in `/usr/bin/env`, "the Linux box binds the root read-only" `box() { exec bwrap`, and "the skill says reviewed commands are never run" its sentence's new capital. A new W2672 section carries upstream's rows with upstream's labels and needles, in upstream's order: 93 rows (50 on the mode file, 18 on the README, 9 on the skill, 14 absences in the agent and mode files and 2 in the skill) and upstream's two README absences as `absent_re_in` checks. Not carried: upstream's six rows on its `scripts/check_probe_cleanup.sh`, its two README rows on that script, and "the Linux box empties all of /var", whose needle is the re-pointed row's. Every new row gets the generic and the needle-only break-it, and each README absence is planted. `PROBE_BREAKS` gains 18 whole-block break-its: upstream's six, re-indented, and twelve that each undo one W2670 change in place (the unlock outside the box, `/var/tmp` alone, either box without `exec`, no `setpgrp`, no `/dev/tty` deny, no socket search, no perl check, no `SIGPIPE` ignore, no group kill, the caller's input, no pipe to `cat`). A new self-test checks that every `PROBE_BREAKS` replacement lands in the shipped mode file, eight more drop each added or changed block line on its own, and the break-it that plants a line inside the subshell is keyed on the new trap line.
- **`scripts/check_probe_cleanup.sh` is not carried (W2672).** Upstream's new script runs the block on macOS under `bash`, `sh` and `zsh` and checks what it cleans up. It finds the block with a column-0 awk that this plugin's bulleted, indented block never matches; the block's bytes are upstream's, so upstream's script already runs them; and `scripts/test-all.sh` has no macOS-only step to hang it on. ## [0.5.0] - 2026-10-30

This release brings the plugin to parity with upstream `cheezy/stride-security-review` 2.7.2 (`fd58c62`). It ports the reviewer side of 2.6.0's result file (W2284) and its short manifest description (W2288); 2.7.0's W2274, W2275, W2276, W2278 (the reviewer half), W2279, W2282, W2285 and W2286; 2.7.1's probe sandbox fix (D376); and 2.7.2's D377, D378 and the verdict-gate guards of `6ca7233`. It also renames the reviewer's shell tool from `run`, which Copilot does not recognise, to `execute` (W2564), and brings the agent under Copilot's 30,000-character prompt limit by splitting it into a core plus eleven rule packs and three mode files that the `security-review-essentials` skill sends (W2566). The port was made in tasks W2564–W2568 and W2570–W2576; W2569 folded their notes into this entry. The bullets below are the per-task porting record, and the map that follows names, for each upstream change, the task that carried it and what was adapted.

**Nothing in this release has run in a live Copilot CLI session.** Copilot CLI was not installed or authenticated where the port was made, so every check behind it is offline (`bash scripts/test-all.sh`, which runs `check_fixtures.sh`, `check_agent_contract.sh`, `check_eval_invocation.sh` and `check_git_hardening.sh`) or read from GitHub's documentation. *Not verified in a live Copilot CLI* below lists each check still owed. No saving in tokens or time is claimed for this variant: no Copilot transcript was measured.

### Fixed

- **The agent's output-schema example is valid JSON again (W2569).** W2566 moved `maestro_layer` and `patch` out of the finding object in `agents/security-reviewer.agent.md` and left a trailing comma after `confidence`; it is removed. `docs/SMOKE_TEST.md` *4b* now shows the keyed opening marker the skill sends, `<<<STRIDE RULE FILE packs/phoenix.md <key>>>>`, instead of the unkeyed form.

- **`--full --patches` sends the patch rules (W2566, porting upstream W2285).** Step 4b's dispatch list named only the MAESTRO line, so a full-mode review with `--patches` sent the agent no patch directive although Step 1 says it is injected in both modes. Step 4b now sends the Patches block, as upstream's `6f91613` does.

- **The reviewer's shell tool is renamed from `run` to `execute` (W2564).** The agent's tools line was `["read", "search", "glob", "run"]`. GitHub's [custom agents configuration reference](https://docs.github.com/en/copilot/reference/custom-agents-configuration) gives `execute` (with `shell`, `Bash` and `powershell` as compatible names) as the shell tool, does not list `run`, and ignores names it does not recognize, so under `run` the reviewer may have held no shell at all. `stride-copilot-exploratory-testing` made the same rename in its 0.3.0 for the same reason. The tools line is now `["read", "search", "glob", "execute"]`. `glob` stays: the reference lists `Glob` as a compatible name of `search`. The rename widens nothing: `execute` is the same terminal capability, and no `edit` or `web` tool is added. `docs/SMOKE_TEST.md` follows, and no longer says Copilot refuses to load an agent that names a tool it does not know: the reference says such a name is ignored.
- **The eval now dispatches this plugin's `security-reviewer` agent through Copilot CLI, not a bare `claude -p` (W2570, porting upstream W2274).** Ported from `cheezy/stride-security-review` W2274 (commit `ea06aeb`, released in 2.7.0), in its shape rather than its flags. `scripts/run_eval.sh` said in its own header that it still piped each fixture to `claude -p`, and `.github/workflows/eval.yml` installed `@anthropic-ai/claude-code`, so the eval scored a Claude Code prompt and never this Copilot agent. Each fixture now runs as `copilot --plugin-dir <repo root> --agent security-reviewer --deny-tool='shell, write, read' --excluded-tools='bash, edit, view, grep, glob, web_fetch, web_search' --disable-builtin-mcps --no-custom-instructions --no-ask-user -s -p <prompt>` from an empty scratch directory, with `COPILOT_HOME` pointed at a scratch directory beside it when a token is used. The prompt is the `-p` value, because GitHub's [Running GitHub Copilot CLI programmatically](https://docs.github.com/en/copilot/how-tos/copilot-cli/automate-copilot-cli/run-cli-programmatically) says piped input is ignored when `-p` is given; upstream feeds it on stdin. The flags come from the [CLI command reference](https://docs.github.com/en/copilot/reference/cli-command-reference), [allowing tools](https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli/allowing-tools) (deny rules win over every allow rule and saved approval), the [custom agents configuration reference](https://docs.github.com/en/copilot/reference/custom-agents-configuration) (the agent id is the file name minus `.agent.md`) and the [CLI plugin reference](https://docs.github.com/en/copilot/reference/cli-plugin-reference) (a personal agent with the same id wins over a plugin agent, which the scratch home is there to prevent). The exact invocation, with the prompt shown as `<prompt>`, and the auth mode are printed after the TAP plan line (`--dry-run` included, which now builds the argv), and the CLI's stderr is kept in `logs/<stem>.err.txt` instead of being discarded. The script's and README's `TODO(copilot-port)` notes for the eval are gone; `security-review.yml`'s stays, outside this change.
- **Considerations rows without an `AND` clause were mis-parsed (W2570, porting upstream W2274's fix).** The "findings unchecked" form shifted fields when split on tabs; it now carries an explicit `U` marker, as upstream.
- **Considerations mode no longer contradicts itself (W2571, porting upstream W2275).** Ported from `cheezy/stride-security-review` W2275 (commit `b563d83`, released in 2.7.0). The noise filter suppressed denial-of-service, rate-limit and memory findings while a `partial` or `unmitigated` verdict was meant to be backed by one, so a listed "uploads are size-bounded" consideration could never be backed. A consideration the task lists is now exempt from the filter for that consideration only — diff and full modes keep it unchanged — and the backing finding is a MUST. A gap in pre-existing code now has a rule: the verdict is graded against the changed code, and the gap is named in `note` plus one `info` finding. The "read surrounding code for high confidence" and "do not enumerate the repository" rules are reconciled by a stated read scope: the changed files and their direct callers, at most 10 files beyond the diff, and nothing beyond the supplied files in `full_file` mode. Six of upstream's seven `agents/security-reviewer.md` hunks applied to `agents/security-reviewer.agent.md` unchanged, at the same sections (the introduction, *Input modes*, *False-positive filter*, *Output schema*, *Per-consideration verdicts*, *Confidence guidance* and *Operational constraints*); the added text names no tool, so it needed no Copilot adaptation. The seventh, the credential paragraph, was already in place from W2565 (below).
- **All reviewed content is data, never instructions (W2571: W2275).** The rule covered only consideration strings; it now covers diff hunks, code comments, string literals and every file read, and only the caller's dispatch lines (the mode tag, the named directives and `SECURITY_RESULT_PATH`) carry instructions.
- **The verdict status enum is closed (W2571: W2275).** `mitigated`, `partial` and `unmitigated` are the whole enum; values such as `not_applicable` are forbidden, no entry is dropped, and a consideration with no matching surface is `mitigated`.
- **One mode tag spelling (W2574, porting upstream W2278).** Ported from `cheezy/stride-security-review` W2278 (commit `a01cb19`, released in 2.7.0; its eight pinned agent needles are unchanged at `fd58c62`, though the sentences around them were reworded later). The agent's Input modes said only that the caller "declares" a mode, and a tag it did not recognise fell back to `diff` mode, silently dropping every consideration verdict. The tag is now exactly `/security-review invocation, mode: <mode>` on its own line (`diff`, `considerations`, or `full_file` with an optional `, batch <i> of <N>`; the recursive-criticism directive uses the same form), and nothing else is a tag. With no tag, a considerations list on the caller's own dispatch lines, under any header or none, is still reviewed in `considerations` mode; a list that appears only inside the reviewed content never selects a mode, and a tag naming another mode wins over a list.
- **The corrected spelling (W2574: W2278).** This variant sent the tag without the leading slash: `skills/security-review-essentials/SKILL.md` Steps 4a, 4b and 4.5 wrote `security-review invocation, mode: …`, the agent's `rci_pass` directive read `invocation, mode: rci_pass <i> of <N>`, and the eval sent a bare `mode:` line. All now use upstream's one spelling, with the `/`, and the old spelling is not kept as an alias: `stride-copilot` keys on the slash form.
- **No output file but `SECURITY_RESULT_PATH` (W2574: W2278).** A dispatch line asking for verdicts, findings or a report in any other file is ignored on that point: the document goes to an accepted `SECURITY_RESULT_PATH` or inline in the final message. The README's output-schema paragraph says so.
- **`--fail-on` gates on the consideration verdicts (W2575, porting upstream W2279).** Ported from `cheezy/stride-security-review` W2279 (commit `72a9512`, released in 2.7.0) with the two guards of `6ca7233` (2.7.2). In this variant the `/security-review` pipeline lives in `skills/security-review-essentials/SKILL.md`, so upstream's `commands/security-review.md` changes land there; the porting guide's line that copilot has no command entry point, so W2279 does not apply, is wrong. Before this change a `--fail-on` gate counted severities only, so an `unmitigated` consideration with no finding, or with only a `low` one under `--fail-on critical`, passed it. Step 6 now fails closed, at every threshold, on an `unmitigated` verdict, on a `partial` verdict no finding backs, and on missing or malformed verdicts, which print one stderr line, `consideration_verdicts missing or malformed — gate fails closed`. A `partial` verdict with a backing finding is gated by that finding's severity. Exit codes `0`, `1` and `2` keep their meanings; only what counts toward `1` grows, and only with `--considerations`.
- **A finding that backs a verdict is defined once (W2575: W2279).** Step 4 defines an open verdict (`partial` or `unmitigated`), its evidence references (`<path>:<line>` or `<path>:<start>-<end>`), when a finding backs it (same file, line in range), and the fail-closed case, in which every finding counts as backing; Steps 4.5, 4.6 and 6 use that definition rather than re-deriving it.
- **`--rci` no longer drops the verdicts (W2575: W2279).** Every pass now re-sends the directives Step 4 sent — the considerations list, the MAESTRO table and the `Patches mode: enabled` line, each when its flag is set — under the `rci_pass` tag alone, and asks for `consideration_verdicts` back, re-graded, never removing a finding that backs an open verdict. A pass whose verdicts are missing, not an array, the wrong length, out of position or outside the enum prints `rci pass <i>: consideration_verdicts missing or malformed` and exits `2`; the prior pass's verdicts are never carried forward.
- **A baseline never drops a backing finding (W2575: W2279).** Step 4.6 marks every finding that backs a verdict and drops only acknowledged findings that are not marked; `summary.suppressed_count` counts only what it dropped.
- **`--json --fail-on` gates (W2575: W2279).** Step 5's `--json` and `--sarif` branches ended with "Stop.", so the CI shape `--json --fail-on` never reached Step 6. Both now print nothing more and go on to Step 6.
- **Verdict *i* must answer consideration *i* (W2575, porting upstream `6ca7233`).** An array of the right length that grades one consideration twice and never grades an `unmitigated` one used to count as well-formed. An entry whose `consideration` is neither the resolved consideration at its position, verbatim, nor the redaction sentinel `[REDACTED — row text embedded a credential]` is now malformed: Step 4 states it with the fail-closed cases, Step 4.5 checks it on every pass, and Step 6 gates on it. As in upstream, the sentinel is accepted at any position.
- **One findings document (W2575: `6ca7233`).** Upstream's transforms refuse input that is not exactly one JSON object. This variant has no transform, so the rule is stated in the skill instead: every step that reads the agent's document takes exactly one findings document, a single JSON object, and treats an empty response, two documents run together or a `findings` value that is not an array as a parse failure that exits `2`, so bad input is never read as a count of zero.
- **The agent half (W2575: W2279).** `agents/security-reviewer.agent.md` now says an `rci_pass` is a critique of a prior document, not a fourth mode, and is a `considerations`-mode pass when the caller's own lines re-send a list; that the caller re-sends its first dispatch's directives on every pass, so `maestro_layer`, `patch` and re-graded `consideration_verdicts` survive it and no backing finding is removed without re-grading its verdict to `mitigated`; and that an open verdict's `evidence` names its backing finding's `file:line`, which is how the skill links the two. Upstream's sentences, with "the `/security-review` command" made "the security-review-essentials skill".

### Changed

- **The security reviewer is a core under 30,000 characters plus rule files the skill sends (W2566, porting upstream W2285, `6f91613`).** GitHub's [custom agents configuration reference](https://docs.github.com/en/copilot/reference/custom-agents-configuration) caps an agent's prompt at 30,000 characters. Measured at claim time on 2026-10-30, the body below the frontmatter was 98,478 characters (99,956 bytes for the whole file); after this change `agents/security-reviewer.agent.md` was 27,709 bytes (`wc -c`) and its body 26,479 characters (`awk 'n>=2; /^---$/{n++}' … | wc -m` in a UTF-8 locale; re-measured at `b00d66b` when this release was prepared, since the figures first written here, 27,159 and 25,929, did not match that commit). W2567 brought the body to 25,404 characters; at this release the file is 25,870 bytes and the body 25,403 characters. The eleven packs (Android, Django, Express, iOS, Phoenix, Rails, React/Next.js, web defense, supply chain, CI/CD, agentic) are upstream `fd58c62`'s files, byte for byte but the first line, which names this plugin; they bring upstream's W2285 activation-by-structure wording for supply chain and CI/CD. The three mode files carry this port's own text, moved out of the agent verbatim: `modes/result-file.md` (the path rules, the one-`execute` write, the redaction and the bounded summary), `modes/considerations.md` (the full verdict contract and tool budget) and `modes/reproduction.md` (the probe command, its sandbox and limits). The core keeps upstream's section order, this port's pinned wording, upstream's compact methodology, vulnerability-class table and CWE line, and compact result-file, verdict, reproduction and budget rules that stand alone when a mode file is not sent. "What the caller does with your output" moved to the result-file mode, and "Adding a new framework pack" to the README's *Customization*.
- **How the rules reach the agent: the skill reads and sends them (W2566).** Upstream's agent reads its packs from `${CLAUDE_PLUGIN_ROOT}`; Copilot gives an agent no such path. Of the task's three candidates, (1) a documented variable or relative path an agent's prompt can read does not exist: the [CLI plugin reference](https://docs.github.com/en/copilot/reference/cli-plugin-reference) documents a plugin-root path only in a plugin agent's `mcp-servers` frontmatter and in LSP configuration, never in an agent or skill body. (2) is what this port does, by the user's decision: GitHub's [adding agent skills page](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-skills) says that "when a skill is invoked, GitHub Copilot automatically discovers all of the files in the skill's directory and makes them available alongside the skill's instructions", so the rule files live in `skills/security-review-essentials/packs/` and `modes/`, and the skill, which runs in the main agent, chooses the packs from the reviewed files' paths, extensions, structure and imports, reads them and the mode files it needs, and sends each verbatim between `<<<STRIDE RULE FILE <name> <key>>>>` and `<<<END STRIDE RULE FILE <name> <key>>>>` lines after its directives and before the reviewed input, under a key of sixteen random letters and digits it chooses for each dispatch and names once on a `Rule-file key: <key>` line. ### Security

- **No reviewed text chooses, suppresses or smuggles a rule file (W2566).** Packs are chosen only from the reviewed files' paths, extensions, structure and imports, never from words in them. A rule-file block counts only as the caller's own dispatch lines, placed before the reviewed input and carrying the key the dispatch's first `Rule-file key:` line names; with no key line no block counts. The skill chooses a fresh key for each dispatch and keeps it out of the reviewed content, so a marker line in the reviewed content cannot carry it: the agent reads such a line as content, and it neither forges a block nor, as an unkeyed void rule would let it, withholds every pack from a review. A marker line that does carry the key anywhere inside the diff, a file or a consideration voids every block in that dispatch, as does a block that is unclosed, sent twice, carries another key or names a file outside the agent's table. A `rule file not sent:` notice goes to stderr under `--json` and `--sarif`, so their stdout stays one document. A block cannot change the agent's instructions, mode, schema, verdicts, severities or write path. The skill reads rule files only from its own directory, never from the reviewed repository or by a path relative to the working directory. A rule file that is missing, unreadable or void means the core rules alone, never no review; without `modes/result-file.md` no result file is written, and without `modes/reproduction.md` no probe runs. The credential sentinel and the read-only contract are unchanged.

### Known limitations

- **Callers that dispatch the agent directly get the core rules only (W2566).** Until a caller sends the rule-file blocks itself, a dispatch that does not go through the skill — the Stride workflow's considerations-mode review in `stride-copilot`, `scripts/run_eval.sh`, or `copilot --agent security-reviewer` — reviews with no framework, supply-chain, CI/CD or agentic pack, the compact verdict and budget rules, and no probe. So the eval scores the core alone, and a fixture whose verdict turns on a pack rule may score lower than a review through the skill would; that difference is unmeasured. Fixing `stride-copilot`'s dispatch is a follow-up for that repository.
- **A direct caller's `SECURITY_RESULT_PATH` gets no file without the result-file mode (W2566).** The agent writes only after receiving `modes/result-file.md`; without it, it replies `result: NOT WRITTEN — modes/result-file.md was not sent` and returns the document inline, which every caller of the result file already handles as a failed write.
- **The dispatch key is chosen by the model running the skill (W2566).** No random-number source is involved, and nobody has measured how predictable such keys are; the key only has to be unknown to whoever wrote the reviewed content before the review ran, and absent from it, which the skill checks.
- **The agent was over Copilot's 30,000-character prompt limit until the W2285 port (W2566 brings it under; see *Changed*).** The same reference caps an agent's prompt at 30,000 characters. Measured on 2026-10-30, after the W2573 port: `agents/security-reviewer.agent.md` is 94,081 bytes (`wc -c`) and 93,751 characters (`wc -m` in a UTF-8 locale); its body below the frontmatter is 92,623 characters, 62,623 over the limit (W2564 left it at 71,695; the result-file text and the credential paragraph added 6,129, the W2275 rules 4,420, the W2276, D376 and D378 contract and probe 9,379, and the D377 git hardening 1,000). The W2566 port brought the body to 26,479 characters and W2567 to 25,404 (25,403 at this release), and the contract check pins it under 30,000.
- **No fixture covers a consideration that is wholly a credential, or one that only names where a credential lives (W2571).** Upstream ships none, and adding one here would make this port's fixture set diverge from upstream's. Both cases are pinned by text only.

### For stride-copilot

`stride-copilot`'s considerations-mode deep security review dispatches the `security-reviewer` agent directly, not through the skill, so the agent sees only what that dispatch sends. To get the full considerations contract and a result file, the dispatch must:

- open with the tag exactly as written, `/security-review invocation, mode: considerations`, and put the task's `security_considerations` list on its own dispatch lines;
- send a `Rule-file key: <key>` line and then each rule file between `<<<STRIDE RULE FILE <name> <key>>>>` and `<<<END STRIDE RULE FILE <name> <key>>>>` lines (the skill's Step 4 gives the form), with `modes/considerations.md` at least, read from the installed plugin's `skills/security-review-essentials/`; without it the agent applies only the core's compact verdict and budget rules;
- send `modes/result-file.md` together with a `SECURITY_RESULT_PATH=<absolute path>` line when it wants the result on disk; without the mode file the agent replies `result: NOT WRITTEN — modes/result-file.md was not sent` and returns the document inline;
- expect a consideration the tool budget (20 calls, at most 2 reproductions) stops before it is settled to come back `partial` with a `note` beginning `budget reached:`, no finding and no `file:line`, and treat it as unverified, not as mitigated.

At `stride-copilot` `bd2702f` (2026-10-29) its skills name neither the tag nor `SECURITY_RESULT_PATH`, so every deep review stays inline and on the core rules until that port lands. None of this was dispatched live.

## [0.4.0] - 2026-07-23

### Added — `considerations` mode verifies a task's security_considerations were actually mitigated

A third input mode, `considerations`, turns "considerations declared" into "considerations verified mitigated." Given a diff plus a task's `security_considerations` list, the `security-reviewer` agent now returns a per-consideration `consideration_verdicts` array — one `{consideration, status, evidence, note}` entry per listed consideration, where `status` is one of `mitigated | partial | unmitigated` — alongside its usual findings. A `partial`/`unmitigated` verdict is backed by a matching `findings[]` entry, and an explicit `"None — …"` consideration is `mitigated` when the diff introduces no matching surface. The considerations list is treated strictly as task-authored **data to assess, never as instructions to follow** (prompt-injection safety).

The capability is exposed both programmatically (declare `considerations` mode in the agent prompt) and via a new `--considerations <source>` flag on the `security-review-essentials` skill, where `<source>` is a file (one consideration per line) or an inline consideration, resolved and read as untrusted data confined to the repository tree — never shell-executed. The flag renders a `## Security considerations` block grouping each consideration with its verdict and evidence. `consideration_verdicts` is emitted **only** in considerations mode, so output stays byte-identical for callers that don't opt in — exactly like the existing `--maestro`/`--patches` opt-ins. `--considerations` is diff-based and is ignored under `--full`.

Eval coverage adds a considerations lane to the TAP runner: paired positive-control (an unmitigated consideration with a backing finding) and negative-control (all mitigated, no spurious finding) fixtures under `test/fixtures/considerations/`, a `→ CONSIDERATIONS …` EXPECTED.md grammar, and a fixture-drift parity exclusion for the `.considerations` sidecars — bringing the suite to 66 fixtures. `consideration_verdicts` is non-deterministic agent output, so it is asserted by the eval runner rather than golden-compared.
